| 项目 | 内容 |
| --- | --- |
| 状态 | 当前产品基线 |
| 更新日期 | 2026-09-03 |
| 平台 | HarmonyOS NEXT |
| 技术 | ArkTS + ArkUI + ArkData |

## 1. 产品定位

动谱是一款**目标驱动的减脂与力量训练执行助手**。

核心承诺：

> 打开动谱，就知道今天该吃多少、蛋白质还差多少、该不该训练、练什么，以及当前减脂趋势是否正常。

当前阶段只追求“真实可用”，不追求功能大而全。

## 2. 当前核心用户

首个完整支持场景：

- 目标：减脂，同时尽量保持或提高力量。
- 训练：每周 3 次必做力量训练，可选第 4 次训练。
- 场景：健身房。
- 偏好：上肢优先，不安排独立腿日，但保留最低有效下肢训练量。
- 日常跟踪：体重、热量、蛋白质、步数、力量训练。

当前 V2 不承诺完整支持 2 练或 5 练 Program，也不承诺居家 Program 已达到正式可用质量。

## 3. 一级导航

固定四个 Tab：

```text
今日    今天还需要做什么
训练    本周计划、开始/继续训练、自定义训练、历史
数据    体重、营养、训练趋势与周复盘
我的    当前目标、身体记录、训练偏好与设置
```

动作库位于训练体系内部，不作为一级入口。

## 4. 今日页

今日页是主入口，只回答“今天还需要做什么”。

必须展示：

- 最近体重与目标体重。
- 7 日体重趋势；数据不足时明确显示数据不足。
- 今日 Checklist。
- 今日热量与蛋白质进度。
- 今日训练状态。
- 今日步数。

今日训练状态必须来自统一业务规则，而不是页面自行根据 `nextRequiredWorkoutIndex` 推测。

目标状态：

```text
存在 active workout
→ 继续训练

本周必做未完成
→ 推荐下一场 Required Workout

本周 3 / 3，用户设置 4 练，Optional 未完成
→ 推荐 Optional

本周 3 / 3，用户设置 3 练
→ 恢复日

本周 Required + Optional 均完成
→ 恢复日
```

完成 3 场必做后，不能再次在同一自然周把 Push 当成新的必做训练催促用户。

## 5. 训练 Program

当前内置 Program：

```text
减脂 · 上肢优先 · 3—4练

Required 1: Push
Required 2: Pull + 后链
Required 3: Upper
Optional: 肩 / 手臂 / 低强度有氧
```

Optional 不计入最低周完成率。

本周训练完成状态必须由 `workout_session` 历史推导，不允许只通过 Program cursor 猜测。

## 6. 训练执行

训练中一次只聚焦当前动作。

需要支持：

- 上次重量/次数建议。
- 重量与次数快速修改。
- 完成本组立即持久化。
- 休息倒计时。
- 动作替换。
- 暂时离开并恢复。
- App 被回收后恢复 active workout。
- 完成训练后进入历史。

### 6.1 渐进超负荷

采用简单 Double Progression：

```text
所有目标工作组达到 repMax
→ 下一次按该动作的 weightIncrementKg 增重，并从 repMin 开始

未全部达到 repMax
→ 重量保持，继续尝试提高次数
```

建议只是默认值，用户始终可以修改。

### 6.2 动作记录类型

当前代码主要按“重量 + 次数”记录。

做到可用版本前必须正确支持自重动作：

```text
自重动作允许 weight = 0
并可正常完成一组
```

后续再考虑 duration、assisted weight 等更复杂记录类型。

## 7. 营养

当前只做低成本记录：

- 早餐 / 午餐 / 晚餐 / 加餐。
- 食物名称。
- 热量。
- 蛋白质。
- 碳水与脂肪可选。
- 快捷食物。

蛋白粉只是快捷食物，不做独立模块。

当前不做：

- 大型商业食物数据库。
- 条码扫描。
- 拍照识别热量。
- 根据运动消耗返还可吃热量。

## 8. 身体与趋势

体重趋势优先使用 7 日窗口，不对单日上涨做负面解释。

状态至少包含：

```text
数据不足
下降偏慢
进度正常
下降偏快
```

状态判断使用周变化百分比，并将阈值集中在 Service/配置层。

腰围是可选辅助指标，不要求每日记录。

## 9. 周复盘

周复盘展示真实记录日口径：

- 体重趋势。
- 腰围趋势。
- Required 完成数 / 3。
- Optional 完成数。
- 本周总训练数。
- 蛋白质达标记录日。
- 有记录天数下的平均热量。
- 有记录天数下的平均步数。
- 可解释的力量亮点。

没有记录的数据应显示“暂无数据”，不能当作 0 参与平均值。

## 10. 当前必须完成的可用性标准

在进入自动调整、健康数据和 AI 之前，用户必须能够稳定完成以下闭环：

1. 首次设置减脂目标。
2. 旧 V1 用户可安全完成 V2 Upgrade，历史训练不丢。
3. 今日页给出正确的 Required / Optional / Recovery 建议。
4. 每周完成 3 场 Required 后不会再次被催 Push。
5. 开始训练、逐组记录、休息、替换动作、完成训练。
6. 自重动作可以正常记录。
7. 中途退出或杀 App 后恢复训练。
8. 记录体重、饮食和步数。
9. 数据页能看到可信的 7 日趋势和周统计。
10. kg/lb 在所有页面显示一致，数据库统一存 kg。
11. Fresh install、V1→最新、V2→V3 数据库路径可验证。

## 11. 当前不做

做到可用版前不新增：

- AI Coach / 聊天页。
- 自动调整热量或步数目标。
- 云账号与云同步。
- 社区、排行榜、积分、连续打卡惩罚。
- 商城和付费课程。
- 多套复杂训练周期。
- 复杂 1RM、训练容量或疲劳模型。

这些能力只有在当前数据闭环稳定并经过真实使用后再评估。
