| 项目 | 内容 |
| --- | --- |
| 文档版本 | 2.0 |
| 状态 | 实施基线 |

| 目标平台 | HarmonyOS NEXT 手机 |
| 技术方向 | ArkTS + ArkUI + ArkData，本地优先 |

## 1. 产品重新定位

动谱从“新手力量训练记录器”升级为**目标驱动的减脂与力量训练执行助手**。

它不试图成为综合健身平台，也不做课程社区、商城或公开计划市场。它解决的是普通健身用户每天最实际的五个问题：

1. 我今天到底该做什么？
2. 今天还能吃多少，蛋白质够不够？
3. 今天练什么、用什么重量、下一次怎么进步？
4. 体重波动到底代表有没有在变瘦？
5. 如果连续两周没有进展，下一步应该调整什么？

一句话承诺：

> **打开动谱，就知道今天该吃什么、练什么，以及离目标还差多少。**

首个重点场景是：用户以减脂为主要目标，每周进行 3—4 次健身房力量训练，希望保住或提高力量，不想安排独立腿日，但接受最低有效的腿部训练量。

## 2. 产品原则

### 2.1 目标优先，而不是功能优先

首页不展示“功能入口集合”，而是展示用户当前目标和今天最需要完成的事情。

### 2.2 给一个明确答案

能给默认建议时，不让用户先做复杂选择。例如：

- 今天建议 Push，而不是先进入动作库挑动作。
- 蛋白质还差 24g 时，直接显示“可补 1 勺乳清蛋白”。
- 体重单日上涨时，不制造“退步”提示，只看 7 日均值趋势。

### 2.3 最少输入

- 一组训练尽量一次点击完成记录。
- 饮食 MVP 只要求热量和蛋白质，碳水、脂肪为可选。
- 常用食物支持一键快捷添加。
- 体重记录默认只填一个数字。

### 2.4 趋势高于单点

体重、腰围、训练和营养都优先展示 7 日或周级趋势，不对单日波动作错误解读。

### 2.5 训练用于保肌和进步

减脂阶段不以“消耗卡路里”衡量力量训练价值。核心训练指标是：训练完成率、动作稳定性、重量/次数是否维持或提高。

### 2.6 本地优先

核心功能在无登录、无服务器、无网络时可完整使用：

- 今日计划
- 体重记录
- 饮食记录
- 训练执行
- 训练历史
- 趋势分析

## 3. 目标用户

### 3.1 核心用户

- 18 岁以上普通成年人。
- 有减脂或体型改善目标。
- 每周可训练 2—5 次，以 3—4 次为核心体验。
- 在健身房训练，但不想研究复杂周期计划。
- 愿意做少量记录，希望软件主动给建议。

### 3.2 当前参考用户配置

用于 V2 首批开发与验收的参考配置：

```text
身高：178 cm
当前体重：约 82 kg
目标体重：75 kg
目标：减脂
每周训练：3—4 次
地点：健身房
偏好：上肢优先，不安排独立腿日
每日目标：约 2100 kcal / 150g 蛋白质 / 9000 步
```

这些值是测试与演示基线，不应被硬编码为所有用户的固定目标。

## 4. 明确不做

V2 MVP 暂不实现：

- 社区、排行榜、连续打卡火焰、积分系统。
- 课程商城、会员内容、教练市场。
- 全量商业食物数据库。
- 条码扫描、拍照识别菜品、OCR 估算热量。
- 根据运动直接“返还”可吃热量。
- 体脂秤品牌接入。
- AI 聊天页或通用 AI Coach。
- 云账号和跨设备同步。
- 复杂 1RM、训练容量、疲劳模型。
- 用单日体重变化自动调整计划。

AI 只有在体重、饮食、训练、步数等核心数据闭环稳定后再进入后续版本。

## 5. 顶层信息架构

底部保留四个一级入口：

```text
今日    今天该完成什么
训练    当前训练计划与训练执行
数据    体重、腰围、营养和训练趋势
我的    目标、身体信息、训练偏好与设置
```

动作库不再占底部一级入口，移动到“训练”内部。

## 6. 首次使用与目标建立

首次设置控制在 1—2 分钟完成。采用逐步页面，一屏只解决一类问题。

### 6.1 目标

选择：

- 减脂
- 增肌
- 保持体型
- 提升力量

V2 MVP 优先完整支持“减脂”；其他目标可以保留入口，但若逻辑未完成必须明确标记“后续支持”，不能伪装为已生成专业方案。

### 6.2 身体数据

必填：

- 身高 cm
- 当前体重 kg
- 目标体重 kg

可选：

- 腰围 cm
- 出生年份
- 性别（仅在确实用于目标计算时询问）

不要求头像、昵称、手机号或账号。

### 6.3 训练条件

- 每周训练次数：2 / 3 / 4 / 5。
- 训练地点：健身房 / 家里。
- 是否安排独立腿日。
- 更偏好器械 / 无明显偏好。

“不安排独立腿日”不等于完全排除下肢。默认语义是：

```text
dedicatedLegDay = false
minimumLegVolume = true
```

### 6.4 饮食记录偏好

- 简单记录：热量 + 蛋白质（默认）。
- 详细记录：热量 + 蛋白质 + 碳水 + 脂肪。
- 不记录具体食物：仅完成行为任务，属于 P1。

### 6.5 生成第一阶段方案

生成页至少展示：

- 当前体重 → 目标体重。
- 第一阶段建议周期。
- 每日热量目标。
- 每日蛋白质目标。
- 每日步数目标。
- 每周训练次数。
- 本周训练结构。
- 对训练偏好的处理说明。

用户必须可以进入“我的 → 当前目标”修改目标值。

## 7. 今日首页

“今日”是整个产品的主入口。首页只回答：**今天还需要做什么。**

### 7.1 顶部目标摘要

展示：

- 当前最近一次体重。
- 目标体重。
- 过去 7 天平均变化。
- 状态标签：数据不足 / 进度正常 / 下降偏慢 / 下降偏快。

不得使用单日体重变化生成负面结论。

### 7.2 今日计划 Checklist

默认最多 5 项：

1. 记录晨重。
2. 饮食记录已开始/已完成。
3. 蛋白质目标。
4. 步数目标。
5. 今日训练（训练日）或恢复提示（非训练日）。

完成进度展示为 `3 / 5`，但不使用“断签惩罚”。

### 7.3 营养进度

至少展示：

```text
热量       1580 / 2100 kcal
蛋白质       92 / 150 g
还可摄入      520 kcal
蛋白质还差     58 g
```

“还可摄入”只基于用户当日目标减去已记录摄入，不减去运动消耗。

提供 `+ 记录饮食`。

### 7.4 今日训练

训练日显示：

- 训练名称。
- 训练部位。
- 动作数量。
- 预计时长。
- 前 3 个动作预览。
- 主按钮“开始训练”。

若存在 active `WorkoutSession`，该区域必须优先变成“继续训练”。

### 7.5 活动

展示：

- 当前步数。
- 今日目标。
- 剩余步数。

P0 允许手动录入或暂使用本地模拟值；P1 再接 HarmonyOS 健康数据能力。

## 8. 训练系统

现有训练执行能力继续保留，但从 A/B 固定计划升级为 Program Engine。

### 8.1 推荐计划结构

首个内置模板：

```text
减脂 · 上肢优先 · 3—4练

A · Push
胸 / 肩 / 三头

B · Pull + 后链
背 / 二头 / 罗马尼亚硬拉

C · Upper
胸 / 背 / 肩 / 少量腿举

D · Optional
肩 / 手臂 / 20—30 分钟低强度有氧
```

D 为可选，不应影响最低周训练完成率。

### 8.2 首批参考动作

#### A · Push

- 卧推：4 × 6—10
- 上斜哑铃卧推：3 × 8—12
- 坐姿推肩：3 × 8—12
- 侧平举：4 × 12—20
- 绳索下压：3 × 10—15
- 三头伸展：2 × 10—15

#### B · Pull + 后链

- 高位下拉：4 × 8—12
- 坐姿划船：3 × 8—12
- 胸托划船：3 × 8—12
- 罗马尼亚硬拉：3 × 8—10
- 面拉：3 × 12—20
- 哑铃弯举：3 × 10—15

#### C · Upper

- 上斜卧推：3 × 8—12
- 高位下拉：3 × 8—12
- 器械推胸：3 × 10—12
- 坐姿划船：3 × 10—12
- 腿举：3 × 10—15
- 侧平举：4 × 12—20
- 二头：3 组
- 三头：3 组

动作 ID 必须映射到审核后的本地动作目录，不允许仅凭中文名称关联。

### 8.3 训练预览

统一展示：

- 动作顺序。
- 计划组数。
- 次数范围。
- 休息时间。
- 预计总时长。

主按钮“开始第一个动作”。

### 8.4 训练中

一次只聚焦当前动作：

- 当前动作和器械。
- 当前第几组 / 总组数。
- 次数范围。
- 上次完成数据。
- 今天建议重量。
- 重量输入。
- 次数输入。
- “完成本组”。

每完成一组立即持久化，然后进入休息倒计时。

### 8.5 渐进超负荷

V2 P1 实现最小 Double Progression：

```text
若上一次训练中所有工作组都达到 repMax：
  建议下一次增加最小重量增量。
否则：
  保持上次重量，目标是增加总次数或提高组间稳定性。
```

建议值不能自动写入已完成记录，用户始终可以修改。

### 8.6 器械被占用

继续保留现有替换动作机制：

- 最多 2 个审核后的等价动作。
- 替换只影响本次训练。
- 无可靠替换时允许“稍后再做”。

## 9. 饮食记录

### 9.1 MVP 模型

第一版不做大型食物库，只支持：

- 早餐 / 午餐 / 晚餐 / 加餐。
- 食物名称。
- 份数。
- 热量。
- 蛋白质。
- 碳水和脂肪可选。

### 9.2 快捷食物

内置可编辑的快捷食物，例如：

```text
1 勺乳清蛋白   120 kcal   24g protein
2 个鸡蛋       140 kcal   12g protein
250ml 牛奶     160 kcal    8g protein
200g 鸡胸      330 kcal   60g protein
无糖酸奶       用户自定义
```

蛋白粉只是食物条目，不做单独“蛋白粉模块”。

### 9.3 快捷建议

当蛋白质明显不足时，可以基于快捷食物生成简单规则提示，例如：

```text
当前 126 / 150g
还差约 24g
建议：可补 1 勺乳清蛋白
```

提示只是执行建议，不应强制用户添加。

## 10. 身体数据与趋势

### 10.1 体重

允许每天记录多次，但趋势计算使用“每日代表值”，MVP 默认取当天最后一次记录。

核心指标：

- 最近体重。
- 7 日移动平均。
- 上一 7 日平均。
- 周变化量。
- 周变化百分比。

### 10.2 腰围

腰围是可选辅助指标：

- 不要求每日记录。
- 建议每 1—2 周记录一次。
- 数据页展示趋势即可。

### 10.3 趋势状态

只有在数据量满足条件时才判断：

- 最近 7 天至少 4 个有效体重日。
- 与前一窗口比较时，两边都应有足够数据。

参考状态：

```text
数据不足
下降偏慢
进度正常
下降偏快
```

阈值必须作为配置常量，不散落在 UI 中。

## 11. 数据页

顶部可切换：

```text
体重 / 训练 / 营养
```

### 11.1 体重

- 7 日平均。
- 与上一周比较。
- 30 天趋势图。
- 目标体重进度。
- 腰围最近变化。

### 11.2 训练

- 本周训练完成 `3 / 3`。
- 最近训练历史。
- 关键动作最近几次重量/次数。
- P1 展示“保持 / 进步 / 明显下降”简单标签。

### 11.3 营养

- 周平均热量。
- 蛋白质达标天数。
- 每日热量目标执行情况。

不展示伪精确的“燃烧卡路里”和“净卡路里”。

## 12. 周复盘

P1 实现每周汇总：

```text
体重 82.0 → 81.6 kg
腰围 91 → 90 cm
训练 3 / 3
蛋白质达标 6 / 7
平均步数 8732
```

并展示关键力量变化，例如：

```text
卧推 60kg × 8 → 60kg × 10
高位下拉 55kg × 10 → 60kg × 8
```

结论采用规则生成，先不调用 LLM。

## 13. 自动调整建议

P2 才进入自动调整，不进入第一阶段实现。

只有在至少连续 14 天具有较完整数据时生成建议，并且一次只推荐一种主要调整：

- 保持不变。
- 小幅增加步数目标。
- 小幅减少每日热量目标。
- 下降过快时增加热量目标。

用户点击接受后才修改目标，禁止后台静默调整。

## 14. 我的

### 14.1 当前目标

- 目标类型。
- 当前体重。
- 目标体重。
- 每日热量。
- 每日蛋白质。
- 每日步数。

### 14.2 训练偏好

- 每周训练次数。
- 训练地点。
- 是否安排独立腿日。
- 器械偏好。

### 14.3 设置

- kg / lb。
- 提醒开关。
- 数据导出（P1）。
- 媒体缓存。
- 隐私说明。
- 数据来源与版权。

## 15. 核心状态优先级

启动应用后按以下顺序决定首页：

1. 数据库未初始化 → 初始化与迁移。
2. Onboarding 未完成 → Onboarding。
3. 存在 active workout → 今日页显示“继续训练”，训练 Tab 同步显示 active 状态。
4. 否则加载今日计划、营养、活动和趋势。

活动训练的恢复优先级高于新建训练。

## 16. MVP 成功标准

V2 P0 完成时，一个首次使用者应该能够：

1. 完成目标、身体信息和训练偏好的首次设置。
2. 得到一个 3—4 练减脂力量计划。
3. 在今日页看到体重、热量、蛋白质、步数和训练任务。
4. 30 秒内记录当天体重。
5. 用快捷食物在 10 秒内记录一勺蛋白粉。
6. 从首页一键进入今天训练。
7. 训练中查看上次重量/次数并完成每一组记录。
8. App 被杀死并重新打开后恢复进行中的训练。
9. 完成训练后在历史中看到完整组记录。
10. 数据页看到 7 日平均体重，而不是只看单日变化。
11. 离线完成上述全部核心流程。

## 17. 开发优先级

### P0：V2 最小完整闭环

- V2 数据库迁移。
- 用户目标与身体数据。
- 新 Onboarding。
- 今日 Dashboard。
- 体重记录。
- 简单饮食与快捷食物。
- 3—4 天训练 Program。
- 训练执行复用与适配。
- 训练历史。
- 7 日体重平均。
- 四 Tab 导航。

### P1：增强执行反馈

- 步数系统接入。
- 腰围趋势。
- Double Progression。
- 周复盘。
- 营养周统计。
- 数据导出。

### P2：智能调整

- 14 天规则分析。
- 热量/步数调整建议。
- 更灵活 Program 模板。
- HarmonyOS 健康数据深度接入。

### P3：AI

只有核心结构稳定后再做：

- AI 饮食自然语言输入。
- AI 周复盘解释。
- AI Coach。
